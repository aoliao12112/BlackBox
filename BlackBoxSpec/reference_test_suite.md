## 测试清单

### T01 — 首次启动空状态

| 项 | 内容 |
|----|------|
| **前置条件** | 全新安装（沙盒为空） |
| **操作步骤** | 启动 App |
| **预期结果** | 进入名片夹首页，显示空状态页面（"还没有名片，点这里扫描" 或类似文案），扫描按钮可见 |
| **验收标准** | 空状态 UI 显示正确；不崩溃 |

### T02 — 进入扫描页面

| 项 | 内容 |
|----|------|
| **前置条件** | 名片夹首页（空或有数据均可） |
| **操作步骤** | 点击右上角扫描按钮 / 空状态页扫描按钮 |
| **预期结果** | 正确进入 ScannerView，显示相机预览画面 |
| **验收标准** | 页面切换流畅；相机画面出现 |

### T03 — 相机权限处理

| 项 | 内容 |
|----|------|
| **前置条件** | 首次进入扫描页，系统尚未请求过相机权限 |
| **操作步骤** | 触发相机启动，系统弹窗请求权限 |
| **预期结果 - 允许** | 相机正常预览 |
| **预期结果 - 拒绝** | 显示权限引导 UI（"请在设置中开启相机权限"），并提供跳转设置按钮 |
| **验收标准** | 两种路径均不崩溃，拒绝路径有明确引导 |

### T04 — 拍摄标准名片

| 项 | 内容 |
|----|------|
| **前置条件** | ScannerView，相机权限已允许，画面中有一张清晰正平面片 |
| **操作步骤** | 点击拍摄按钮 |
| **预期结果** | 抓拍成功，进入 CardBoundaryView 开始边界检测 |
| **验收标准** | 无崩溃，正确进入检测流程 |

### T05 — 从相册导入

| 项 | 内容 |
|----|------|
| **前置条件** | ScannerView |
| **操作步骤** | 点击相册导入按钮，选择一张名片图片 |
| **预期结果** | 图片导入成功，进入边界检测流程 |
| **验收标准** | 导入/权限拒绝两种路径都正确处理 |

### T06 — 名片边界检测（倾斜场景）

| 项 | 内容 |
|----|------|
| **前置条件** | 拍摄/导入的名片有明显倾斜（~30° 旋转 + 梯形透视） |
| **操作步骤** | 进入 CardBoundaryView |
| **预期结果** | 自动检测到名片边界，显示黄色/白色四边形描边框，点击确认后名片被自动校正为正面矩形 |
| **验收标准** | 校正后名片边缘对齐画面边界；若自动检测失败需有手动调整入口 |

### T07 — OCR 识别产生原始文本

| 项 | 内容 |
|----|------|
| **前置条件** | 校正后的清晰名片图 |
| **操作步骤** | 确认进入 OCR 流程 |
| **预期结果** | OCR 运行完成，产生非空的 rawText，显示在 OCRResultView |
| **验收标准** | 生成 OCR Raw Text 并持久化到 BusinessCard.ocrRawText；空结果需走 E4 异常路径 |

### T08 — 结构化字段正确分类

| 项 | 内容 |
|----|------|
| **前置条件** | OCR Result（使用教师 Ground Truth 测试卡） |
| **操作步骤** | 进入 FieldCorrectionView |
| **预期结果** | 正确识别出姓名、公司、职位、手机、Email 等字段，分类正确（用 Ground Truth 比对） |
| **验收标准** | 字段级准确率达标；错误分类需要人工校正 |

### T09 — 缺失字段不得补全

| 项 | 内容 |
|----|------|
| **前置条件** | 使用一张 **没有 Website 字段** 的测试名片 |
| **操作步骤** | 完成 OCR + 字段抽取 |
| **预期结果** | BusinessCard.website = nil，AI 不得凭空生成网址 |
| **验收标准** | 缺失字段为 nil；这是特别重要的一条 |

### T10 — 多电话号码正确区分

| 项 | 内容 |
|----|------|
| **前置条件** | 名片上同时有 Mobile / Office / Fax 三个号码 |
| **操作步骤** | 字段抽取 |
| **预期结果** | mobile、officePhone、fax 分别填入各自字段，不混填 |
| **验收标准** | 三个字段独立；号码文本正确 |

### T11 — 人工修正后保存

| 项 | 内容 |
|----|------|
| **前置条件** | FieldCorrectionView，AI 将公司名误分类为姓名 |
| **操作步骤** | 用户手动修改 name 和 company 字段，点击"保存" |
| **预期结果** | 保存后的 BusinessCard 字段值 = 用户修改值；FieldConfidence 标记该字段 source = .manual |
| **验收标准** | 修正值正确持久化；不丢失其他未修改字段 |

### T12 — 保存成功返回名片夹

| 项 | 内容 |
|----|------|
| **前置条件** | FieldCorrectionView，字段已确认 |
| **操作步骤** | 点击"保存" |
| **预期结果** | 返回 HomeView；名片夹列表出现新条目；列表按创建时间倒序 |
| **验收标准** | 新名片可见；刷新后仍在 |

### T13 — 名片详情页完整显示

| 项 | 内容 |
|----|------|
| **前置条件** | HomeView 有已保存名片 |
| **操作步骤** | 点击某条名片 |
| **预期结果** | 进入 CardDetailView；显示：原图 / 校正图 / 所有非空字段 / 标签 / 备注 |
| **验收标准** | 字段值与保存时一致 |

### T14 — 编辑后字段正确更新

| 项 | 内容 |
|----|------|
| **前置条件** | CardDetailView |
| **操作步骤** | 点"编辑"，修改公司名称，保存返回 |
| **预期结果** | DetailView 立即显示新公司名；updatedAt 更新 |
| **验收标准** | 再次进入仍为新值 |

### T15 — 搜索返回正确结果

| 项 | 内容 |
|----|------|
| **前置条件** | 名片夹有 ≥2 张名片，其中一张 name = "张三" |
| **操作步骤** | 搜索 "张" |
| **预期结果** | 列表只显示匹配的名片 |
| **验收标准** | 搜索范围包含 name / company / jobTitle / mobile / email |

### T16 — 标签筛选

| 项 | 内容 |
|----|------|
| **前置条件** | 一张名片添加了 "Conference" 标签 |
| **操作步骤** | 创建标签 → 给名片添加 → 按标签筛选 |
| **预期结果** | 筛选页只显示带该标签的名片 |
| **验收标准** | 标签删除 → 所有名片从该标签移除 |

### T17 — 删除名片

| 项 | 内容 |
|----|------|
| **前置条件** | HomeView |
| **操作步骤** | 左滑删除 → 确认弹窗 → 删除 |
| **预期结果** | 名片从列表消失；持久化数据同步删除 |
| **验收标准** | 删除后重新启动 App 也不再出现 |

### T18 — 持久化（Kill App 重启）

| 项 | 内容 |
|----|------|
| **前置条件** | 已扫描 + 人工修改 + 保存一张名片 |
| **操作步骤** | Kill App（双击 Home 上划）→ 从 SpringBoard 重新启动 |
| **预期结果** | 名片夹仍有该名片；打开后所有字段、图片、标签、备注与上次退出前完全一致 |
| **验收标准** | T18 是持久化核心验证；若重启丢数据则 Week 5 未完成 |

### T19 — 导出到系统联系人 / VCF

| 项 | 内容 |
|----|------|
| **前置条件** | 详情页 |
| **操作步骤** | 点击"导出" → 选择导出方式 |
| **预期结果** | 系统联系人 / VCF 文件包含正确字段：name / company / jobTitle / phone / email / address |
| **验收标准** | 无字段丢失、无乱码 |

### T20 — 异常路径全覆盖

| 项 | 内容 |
|----|------|
| **覆盖场景** | 取消扫描返回 / 拍摄后取消 / 相册权限拒绝 / 相机权限拒绝 / OCR 完全失败 / 边界检测失败 + 手动调整 / 保存中磁盘满 |
| **验收标准** | 每条异常路径都有用户可理解的反馈、不崩溃、状态正确回退 |
